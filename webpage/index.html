Cosmos3-Nano T2V — Training-free 2.36x Acceleration

Stack a derivative cache, FP8 quantization, and quantized dense attention to reduce text-to-video latency while preserving final8 quality gates.

SECTION 0

Background & Setup

Stack three orthogonal training-free levers — a derivative CACHE (TaylorSeer), weight+activation QUANTIZATION (M1, FP8), and quantized dense ATTENTION (M2 SageAttention2) — to cut latency 2.36x vs BF16 with no quality regression. A fourth lever, block-sparse attention (A2), was explored but not shipped — it degraded large-object motion (see the appendix).

Delivered 2.36x vs BF16 cache + M1 + M2, quality-gated on final8

Three orthogonal levers (delivered)

  1. Cache — TaylorSeer derivative cache (training-free).
  2. Quant — M1 FP8 W8A8 + SmoothQuant.
  3. Attention — M2 SageAttention2 dense (INT8-QK + FP8-PV).

Environment / Install

  1. Python 3.13, single H200 (Hopper sm90), CUDA 12.8 toolchain (cu128 torch backend).
  2. venv via uv: uv venv venv --python 3.13 --seed --managed-python then uv pip sync tools/requirements.lock --torch-backend cu128.
  3. Pinned (from tools/requirements.lock): torch 2.11.0+cu128, torchvision 0.26.0+cu128, triton 3.6.0, transformers 5.12.0, accelerate 1.14.0, and diffusers installed from GitHub main (pinned commit a50ade49) for Cosmos3OmniPipeline.
  4. TorchAO ~0.17.0 (version=2 quant API; provides Float8DynamicActivationFloat8WeightConfig with PerRow granularity) — installed separately.
  5. SageAttention2 / SpargeAttn: built EDITABLE from github.com/thu-ml/SpargeAttn (SpargeAttn layers block-sparsity on top of SageAttention2++ INT8-QK + FP8-PV kernels). Build-environment notes: set TORCH_CUDA_ARCH_LIST=9.0, CUDA_HOME=/usr/local/cuda-12.8, remove the -include,cassert line from its setup before building, and avoid conda header pollution (build against the venv, not a conda env).
  6. Repo is self-contained: the M1 SmoothQuant calibration stats m1_smoothquant_stats/act_absmax.pt are committed in-repo (no separate calibration download needed).

SECTION 1

Cache — TaylorSeer derivative cache

Training-free. On non-full steps, predict transformer block output deltas via an order-1 Taylor expansion from recent full-step activations instead of recomputing. Config i2_o1_all_w1_c5 = interval 2 (full recompute every 2 steps), max-order 1, first-enhance 1, last-enhance 5; also caches the unconditional/und branch; applied to all blocks.

Speedup 1.61x over BF16 264s -> 164s, no quality loss

venv/bin/python tools/diffusers_taylorseer_t2v_benchmark.py --model nvidia/Cosmos3-Nano --dtype bf16 \
  --prompt-json assets/cosmos3_t2v_prompts_seed100_upsampled/prompts/prompt_068.json \

  --taylorseer-cache-max-gib 120 --save-video out.mp4

SECTION 2

M1 — FP8 W8A8 + SmoothQuant

Quantize the 252 generation-pathway linear layers (36 transformer layers x 7 projections) to FP8 E4M3 weights + activations (TorchAO Float8DynamicActivationFloat8WeightConfig, PerRow, lowers to rowwise _scaled_mm). SmoothQuant alpha=0.5 migrates activation outliers into weights (fold-free, into RMSNorm + linear input columns), calibrated on the 100 structured prompts. Per-layer torch.compile of the real TaylorSeer hot path so the FP8 cast fuses. alpha=0.5 is the sweet spot — alpha 0 or 0.6 collapse high-motion 068.

Speedup 1.23x over cache 164s -> 133s; 1.98x over BF16; 8/8 final8

= config B base flags, but using tools/diffusers_m1m2_t2v_benchmark.py and adding:

Repro — config C (M1 delta) 
--attention-backend native --m1-fp8 --m1-compile --m1-smoothquant --smoothquant-alpha 0.5 \
  --smoothquant-stats-path m1_smoothquant_stats/act_absmax.pt

SECTION 3

M2 — SageAttention2 quantized attention

Replace the generation self-attention with SageAttention2's INT8 QK^T + FP8 PV kernel (sm90), behind diffusers' dispatch_attention_fn. q/k arrive already RoPE'd + QK-normed; GQA 32 query / 8 KV heads, head_dim 128; registered as an opaque torch.library custom_op so torch.compile stays fullgraph. Co-design: M2 alone fails 068, but M1's SmoothQuant-cleaned activations give it enough margin.

Speedup 1.47x over cache ~2.36x over BF16, 8/8

= config C, prefixed with env M2_PV_VARIANT=fp8 and switching --attention-backend native → sparge:

Repro — config D (M2) 
M2_PV_VARIANT=fp8 venv/bin/python tools/diffusers_m1m2_t2v_benchmark.py [base + M1 flags] --attention-backend sparge

SECTION 4

Final — full route & time breakdown

BF16 → +cache (×1.61) → +M1 (×1.23) → +M2 (×1.20) = 2.36x over BF16, 8/8 on the final8. The delivered pipeline ends at cache+M1+M2 (dense attention); sparse attention was explored but not shipped — see the appendix.

Delivered route ~2.36x over BF16 cache + M1 + M2, 8/8 on final8
Config Latency (s) Stage gain Cumulative vs BF16 final8
BF16 263.7 — 1.00x baseline
+cache 164.0 1.61x 1.61x 8/8
+M1 133.4 1.23x 1.98x 8/8
+M2 111.5 1.20x 2.36x 8/8

Attention dominates throughout. Cache halves every stage (skips ~half the steps); M1 collapses linear-GEMM 58->19 s and adds a ~9 s FP8-cast prologue; M2 cuts dense attention 84->61 s; VAE decode (~6.3 s) is fixed. Total GPU kernel time falls 252.2 s -> 108.2 s across the delivered ladder; wall-clock is slightly higher.

APPENDIX · EXPLORED, NOT SHIPPED

Sparse attention — explored, not shipped

A self-written window+anchor quant-SPARSE fused kernel: a static block-sparse mask LUT layered on top of the SageAttn2 INT8-QK + FP8-PV mainloop. The mask keeps a contiguous temporal window (ANC_WLOCAL) around each query frame plus a set of fixed global keyframe anchors (ANC_KEYFRAMES=0,8,16,24,32,40,47); the int32 LUT is precomputed once, so per-step overhead is zero and mask-all-1 is bit-equivalent to dense. Shrinking the window raises the block-skip ratio and the speedup — but also the quality cost.

Outcome not adopted every config — down to the mildest 1.04x — loses dense motion; delivered pipeline stops at cache+M1+M2
Sparsity ladder Slide from aggressive (worst) to mild — degradation persists throughout Each step loads the dense cache+M1+M2 (LEFT) versus that sparse config (RIGHT) for the 4 selected prompts. Defaults to the most aggressive variant so the motion loss is immediately visible.

As sparsity and speedup rise, motion and quality degrade — large slow-moving subjects (the 049 steam train, the 079 ship) freeze or smear. Even the mildest config (w32, 1.04x over dense, only 8% block skip) does not fully restore the dense motion, so its quality loss is still not acceptable. This defect is invisible in single still frames — it is a cross-frame motion failure — and was only caught on video. Therefore sparse attention is NOT adopted; the delivered pipeline stops at cache+M1+M2. We also profiled the aggressive 1.3x sparse variant (w10): its per-stage trace shows it does cut attention further (61 -> 34 s), but the motion/quality regression made it not worth shipping.

= config D, prefixed with the anchor-sparse env and switching to the sparse runner script (<w> = the window value, e.g. 10):

Repro — config E (sparse, ANC_WLOCAL) 
M2_PV_VARIANT=fp8 ANCHOR_SPARSE=1 ANC_WLOCAL=<w> ANC_KEYFRAMES=0,8,16,24,32,40,47 \
  venv/bin/python tools/diffusers_m1m2sparse_t2v_benchmark.py [base + M1 flags] --attention-backend sparge
