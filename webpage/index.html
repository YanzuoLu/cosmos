SECTION 0

Background & Setup

Stack three orthogonal training-free levers — a derivative CACHE (TaylorSeer), weight+activation QUANTIZATION (M1, FP8), and quantized dense ATTENTION (M2 SageAttention2) — to cut latency 2.36x vs BF16 with no quality regression. A fourth lever, block-sparse attention (A2), was explored but not shipped — it degraded large-object motion (see the appendix).

Delivered 2.36x vs BF16 cache + M1 + M2, quality-gated on final8

Three orthogonal levers (delivered)

  1. Cache — TaylorSeer derivative cache (training-free).
  2. Quant — M1 FP8 W8A8 + SmoothQuant.
  3. Attention — M2 SageAttention2 dense (INT8-QK + FP8-PV).

SECTION 1

Cache — TaylorSeer derivative cache

Training-free derivative cache. Every interval denoising steps the model does one full backbone compute and stores each of the 36 MoT layers' generation-pathway residual; on the intervening non-full steps it does NOT recompute — it forecasts each layer's residual delta (prediction_target=layer_delta) by Taylor-extrapolating from the cached factors, turning "reuse the last feature" into "predict the next feature." Config i2_o1_all_w1_c5 decodes as: interval 2 (one full recompute every 2 steps), max-order 1 (first-derivative / linear extrapolation), first-enhance 1 (force full compute on the first step), last-enhance 5 (force full compute on the last 5 steps, where the trajectory is most error-sensitive), cache all 36 layers, and also cache the unconditional/und branch so both CFG branches are accelerated.

How the forecast works

  • Finite-difference Taylor, order 1. From the cached full-step features the cache estimates a first derivative across steps, then linearly extrapolates the residual for the skipped steps — a finite-difference Taylor expansion, not a stored copy. A slope_scale knob (1.0 here = undamped) can damp the linear term.
  • Enhance windows guard the endpoints. The first and last steps shape the most of the final image, so they are forced to full compute (first-enhance 1, last-enhance 5) while the cheap middle steps are forecast.
  • Pareto pick. A final8 sweep put three configs on the frontier (mean 1.61x–1.76x); i2_o1_all_w1_c5 (1.61x) is the conservative knee chosen as the frozen base that M1/M2 stack on top of.

Source TaylorSeer — "From Reusing to Forecasting: Accelerating Diffusion Models with TaylorSeers," which forecasts cached features via a Taylor expansion of their step-derivatives rather than naively reusing them. Adapted here to Cosmos3-Nano's per-layer generation residual.

SECTION 2

M1 — FP8 W8A8 + SmoothQuant

Quantize exactly the 252 generation-pathway linears (36 transformer layers x 7 projections: add_q/k/v_proj, to_add_out, and the MoE gen gate/up/down_proj) to FP8 E4M3 weights + activations via TorchAO's Float8DynamicActivationFloat8WeightConfig with PerRow granularity — per-token dynamic activation scale + per-channel weight scale, lowering to a rowwise torch._scaled_mm (trace-verified as a real aten::_scaled_mm, not fake-quant). The understanding/causal pathway, every RMSNorm, softmax and the VAE stay BF16. SmoothQuant (alpha=0.5) migrates the activation outliers into the weights so FP8 can represent both cleanly. Per-layer torch.compile is mandatory and must wrap the real TaylorSeer hot path so the FP8 cast fuses into the GEMM prologue.

SmoothQuant migration & the compile hot-path

  • Fold-free outlier migration. Per-input-channel activation absmax is calibrated once over the 100 structured prompts (cache OFF during calibration to walk the true denoising trajectory; stats committed in-repo, alpha-independent). The migration scale s_j = max(|X_j|)^α / max(|W_j|)^(1-α) folds 1/s into the preceding RMSNorm weight and s into the linear's input columns — zero extra runtime cost (0.999x vs FP8-only).
  • Only the norm-fed linears get migrated. Migration applies to the linears that have a preceding RMSNorm to absorb 1/s — add_q/k/v_proj (via input_layernorm_moe_gen) and gate/up_proj (via post_attention_layernorm_moe_gen); to_add_out and down_proj have no preceding norm and keep plain FP8.
  • Compile must wrap forward_with_gen_delta. The TaylorSeer full step runs Cosmos3VLTextMoTDecoderLayer.forward_with_gen_delta, not the plain forward; compiling the plain forward leaves the cast un-fused and makes FP8 slower than BF16. Per-layer torch.compile(forward_with_gen_delta, fullgraph=True, dynamic=False) fuses the per-token cast into the _scaled_mm prologue (quant overhead 18.6% → 4.4%) while leaving TaylorSeer's Python control flow outside the graph.
  • α is a pure quality knob (speed-invariant); 0.5 is the sweet spot. The high-motion hardcase 068 is the universal quant stress-test: α=0 (FP8-only) under-protects activation outliers → 068=6, 7/8 fail; α=0.5 → 068=7, 8/8 PASS; α=0.6 over-migrates into weight outliers → 068=4, 068 melts.

Source SmoothQuant (Xiao et al., 2022, arXiv:2211.10438 — per-channel activation→weight outlier migration) + TorchAO (github.com/pytorch/ao, the FP8 Float8DynamicActivationFloat8WeightConfig + _scaled_mm lowering). Composition onto the TaylorSeer hot path is ours.

SECTION 3

M2 — SageAttention2 quantized attention

Replace the generation self-attention (the is_causal=False call) with SageAttention2's INT8 QKT + FP8 PV kernel on Hopper sm90 (sageattn_qk_int8_pv_fp8_cuda_sm90), dispatched behind diffusers' dispatch_attention_fn so only the gen path is intercepted — the und/causal path stays native. q/k arrive already RoPE'd + QK-normed and are NOT re-applied; GQA is expanded 32 query / 8 KV heads, head_dim 128, NHD layout, BF16 in/out (single-op cosine vs SDPA = 0.99925). The call is registered as an opaque torch.library custom_op (m1m2::sparge_fp8_dense_sm90) so it composes inside M1's fullgraph=True compiled region without a graph break.

Integration & co-design notes

  • Opaque custom_op keeps compile fullgraph. A naive sage call graph-breaks fullgraph=True. Registering it as a torch.library.custom_op with an explicit schema + fake/meta impl makes Inductor treat it like _scaled_mm (a black box) — trace-verified that both aten::_scaled_mm (the M1 linears) AND the sage sm90 kernel fire across all 36 layers with no graph break.
  • Co-design synergy (measured, not assumed). The high-motion hardcase 068 again gates the stack: M2's attention quant alone warps 068, but M1's SmoothQuant-cleaned activations feeding attention give 068 just enough margin to pass — cache+M1+M2 reaches 068=7 (3 independent raters 7/8/8) and 8/8 overall (mean 8.0).
  • FP8-PV is the only positive-speedup option on Hopper. The FP16-PV variant (sageattn_qk_int8_pv_fp16_cuda) lowers to an SM80-style kernel with no sm90 fast path → negative speedup (0.75–0.89x). It recovers 068 on its own but costs more than it saves, so the FP8 sm90 path is used.

Source SageAttention2 / SpargeAttn (thu-ml) — INT8-QK + FP8-PV Hopper attention kernels: github.com/thu-ml/SageAttention and github.com/thu-ml/SpargeAttn. The dispatch_attention_fn integration + custom_op wrapping into the compiled stack is ours.

SECTION 4

Final — full route & time breakdown

BF16 → +cache (×1.61) → +M1 (×1.23) → +M2 (×1.20) = 2.36x over BF16, 8/8 on the final8. The delivered pipeline ends at cache+M1+M2 (dense attention); sparse attention was explored but not shipped — see the appendix.

APPENDIX · EXPLORED, NOT SHIPPED

Sparse attention — explored, not shipped

A self-written quant+SPARSE fused kernel: a static block-sparse mask (a precomputed int32 LUT) layered on top of the SageAttn2 INT8-QK + FP8-PV no_pv mainloop, registered as the same opaque custom_op (m1m2::sparge_sta_static_sm90) so it composes inside the M1 fullgraph compile exactly like the dense M2 op. Because the mask is static per geometry there is zero per-step mask overhead (no block-map recompute), and a mask-of-all-1s is bit-equivalent to dense — a clean correctness anchor. It deliberately reuses the stable quant mainloop and never touches the deadlocking fused PV-threshold WGMMA path. The winning mask form (A2) is the union of a full-spatial contiguous temporal window (ANC_WLOCAL) around each query frame plus a small set of fixed global keyframe anchors (ANC_KEYFRAMES=0,8,16,24,32,40,47) kept by every query. Shrinking the window raises the block-skip ratio and the speedup — but also the quality cost.

The 5-candidate sparsity sweep

Five mask structures were swapped into the same fused kernel and gated on the strict 8/8 final8 rubric. window+anchor won.

  • STA (sliding-tile) — full-spatial contiguous 3D tile; 8/8 at ±20 temporal (32.5% skip, 1.17x over dense). Found the key rule: high-motion video is sparsity-tolerant on the temporal axis only — full spatial coverage is mandatory.
  • Axial (T/H/W cross-lines) — 76.9% skip / ~1.5x but NO-GO: off-axis spatial loss ghosts/duplicates high-motion subjects (068=3, 028=2).
  • Dilated temporal (full-spatial + strided far frames) — 41–57% skip but NO-GO: per-query relative striding can't interpolate fast motion → 068 ghosting/doubling.
  • Window + global keyframe anchor (A2) — full-spatial ±10 window + 7 fixed keyframe anchors; 50% skip, 8/8, 1.32x over dense. The absolute anchors are the same frames for every query (a consistent global reference), so they add context without dilated's relative-stride ghosting and let the local window shrink from ±20 to ±10. The winner.
  • Content-adaptive — NO-GO: the window/quality frontier is sharp (068 collapses at ±7 and ±4), so a complexity classifier carries a catastrophic false-negative (melting) for no validatable headroom; per-step overhead negates the skip. Static A2 (±10, 50%) is the confirmed ceiling.

Source Self-written kernel — our own static block-sparse mask layered on the SageAttention2 / SpargeAttn INT8-QK + FP8-PV mainloop (thu-ml: SageAttention, SpargeAttn), drawing on sliding-tile / STA and global-anchor (LVSA-style) structured-sparsity ideas. The mask design, LUT, custom_op, and the honest motion-degradation finding are ours.

Outcome not adopted every config — down to the mildest 1.04x — loses dense motion; delivered pipeline stops at cache+M1+M2
Sparsity ladder Slide from aggressive (worst) to mild — degradation persists throughout Each step loads the dense cache+M1+M2 (LEFT) versus that sparse config (RIGHT) for the 4 selected prompts. Defaults to the most aggressive variant so the motion loss is immediately visible.

As sparsity and speedup rise, motion and quality degrade — large slow-moving subjects (the 049 steam train, the 079 ship) freeze or smear. Even the mildest config (w32, 1.04x over dense, only 8% block skip) does not fully restore the dense motion, so its quality loss is still not acceptable. This defect is invisible in single still frames — it is a cross-frame motion failure — and was only caught on video. Therefore sparse attention is NOT adopted; the delivered pipeline stops at cache+M1+M2. We also profiled the aggressive 1.3x sparse variant (w10): its per-stage trace shows it does cut attention further (61 -> 34 s), but the motion/quality regression made it not worth shipping.
